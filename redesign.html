Anonymization Redesign

A modular rethink of the four-stage anonymization pipeline: a fast bi-encoder for detection, entity-level identity resolution with a learned pairwise merger, EAG features alongside, and an LLM-driven faker.

Status: Draft apps/server/data-acq Detection · IR · Faker · Replacer 2026-07

Summary

One pipeline, four stages, redesigned so the expensive model runs once and its output gets reused.

The pipeline still does the same job: find sensitive values in raw customer data, decide which ones refer to the same real entity, and swap each for a consistent fake while preserving format and structure. The redesign changes how each stage works, and it rebalances where the cost goes.

Three changes:

  • Detection becomes a bi-encoder. One encoder produces an embedding per span, and a 20-head attribute classifier (softmaxed over 21 scores, the 20 types plus a non-PII flag) picks the type. It's the most expensive model in the pipeline, so we run it once and reuse the same embedding in IR.
  • IR goes entity-level. We cluster entities, not raw strings, and reuse the detector's embedding instead of re-encoding. FAISS ANN proposes merge candidates and an order-agnostic model scores each pair using the embedding, lexical signals, and EAG features. Only three clusters need IR: Identity, Street, Institution.
  • The LLM moves to faker. We take it out of detection and put it in faker, generating coherent fake identities that map onto the IR clusters.

1 · Detection

Replace two LLM passes with one bi-encoder and a small softmax head.

We've tried a few detectors: GLiGuard, NER, and local LLMs. The plan is to settle on one, most likely a bi-encoder, that turns each candidate span into an embedding. That embedding feeds a 20-head attribute classifier plus a non-PII flag, softmaxed to 21 scores; the argmax picks the type, which maps to its cluster and resolver via the taxonomy above.

Today

  • Two LLM passes. Gemini 2.5 Flash detects spans (batched ~15 texts / 15k chars), then Gemini 2.5 Pro classifies each value against a ~76-attribute taxonomy (batched 50).
  • Every classify batch carries the full taxonomy prompt. It's slow, expensive, and dominates pipeline latency.
  • No embedding survives the stage, so IR later re-encodes with a separate model.

Redesign

  • One bi-encoder embedding per span, then a 21-way softmax picks the type.
  • No per-value LLM call.
  • The embedding is kept and handed to IR.

The EAG, alongside

The Enterprise Activity Graph builds from the same raw data during detection and hands IR extra evidence.

The EAG's graph-init pass does PII detection and entity marking, the same work detection does, and can supersede it. Alongside that it assembles a typed graph of activities, contexts, and identities. Its job for IR is to distill features. It supplements the merger, it doesn't replace it, and IR reads these signals in addition to the embedding and lexical features already on each pair.

What IR reads from the EAG

  • 8 pair features (per the EAG's Features for IR Consumption spec): rare_context_overlap, cooccur_weight, shared_context_count, adamic_adar_context, direct_interaction_count, active_period_jaccard, content_embedding_cosine, same_person_rejected_count.
  • Structural anchors: SAME_PERSON_CONFIRMED from profile-table rows (a Stage-0a pass that resolves ~80% of within-service identity equivalences for free) as zero-cost pre-merges, and SAME_PERSON_REJECTED from an author and a recipient of the same message as hard cannot-links.
  • Activity attributes (pii_density, pii_category_distribution) to weight or filter noisy sources before scoring.

"EAG" here means Enterprise Activity Graph. (An older, unrelated "Embedding-Anchor-Graph" was removed in the current IR engine; different thing, same acronym.)

2 · Identity Resolution

Cluster entities, not strings, and reuse the detector's embedding.

The key shift: contextual embeddings, not string de-dup Today the pipeline de-dups identical strings, so 100 people named "Jane" collapse into a single Jane node and can only ever become one entity and one fake. In the redesign the encoder self-attends over each mention's surrounding context, so those 100 "Jane"s get 100 different embeddings, and IR can split them into distinct entities (merging only the ones that are genuinely the same person). The faker then keeps a running map of every replacement it makes, so each occurrence is faked consistently, while IR is what guarantees each Jane belongs to exactly one entity.

IR takes the bi-encoder embeddings from detection and resolves the three IR clusters, Identity, Street, and Institution, into entities. FAISS ANN over the embeddings proposes merge candidates. An order-agnostic model scores each candidate and returns a calibrated probability that the two are the same entity; high means merge. The score is symmetric, so it doesn't depend on ordering. Confirmed merges compose into clusters, and those clusters are what faker anonymizes.

Most of this is already built The learned machinery here — FAISS ANN candidate generation, the GBDT pairwise merger, calibrated P(merge), and learned per-type thresholds — already exists in the shipped v2 IR engine. The genuinely new parts of this redesign are entity-level clustering, reusing the bi-encoder detection embedding (one encode, two uses) instead of a separate encoder, and the tighter 3-cluster taxonomy.

Old prod (string-level)

  • Re-embed values with a separate MiniLM, score edges with hand-tuned signals, cut one graph with Leiden.

Redesign (entity-level)

  • Reuse the detector's embedding, FAISS ANN candidates, learned order-agnostic merger.
  • Features: embedding + lexical + EAG signals → calibrated P(merge), learned per-type thresholds.

The merger: a GBDT today, room to grow

The pairwise scorer is a gradient-boosted tree (LightGBM). We're still data-poor, and a GBDT handles monotone constraints and native categoricals well at this scale. The feature set has grown from the original 19 production features, through a ~90-feature expansion, to today's 259, spanning string, phonetic, embedding, co-occurrence, and graph families. As labeled data accumulates, the next step is an MLP over the same feature space, eventually one that shares the encoder representation end-to-end. The scorer is a clean interface, so swapping it is contained.

Grounded in Saahil's experiments The merger comes out of a long experiment sweep (his IR-v2 engine explainer and experiments write-up). The findings that shaped it:
  • Co-occurrence is the strongest signal — it recovers same-person pairs no string or embedding match can.
  • The clustering step matters more than the scorer. A strong pairwise model collapsed under naive single-linkage until average-linkage clustering fixed the chaining.
  • Fine-tuning the encoder flips embedding cosine from a liability into a strong positive signal.
  • A cross-encoder and an LLM judge weren't worth their cost over the calibrated GBDT.

3 · Faker

Keep the deterministic guarantees, add an LLM to generate coherent identities.

Today's faker is fully deterministic and seeded, and that spine is worth keeping. The redesign adds an LLM to generate semantically continuous fake identities: personas whose name, email, username, and handle cohere and fit their context. Those get mapped onto the IR clusters to produce the anonymized clusters.

Today (deterministic)

  • Per-cluster seed (SHA256) by priority: email, then full name, then username, then first member.
  • Type-aware router: 114 BII types to ~64 methods, preserving format, casing, and structure.
  • A persona cache shares one fake first/last across an Identity cluster; a global name map keeps the same original mapping to the same fake everywhere.
  • Two passes (anchors, then masked-variant transfer) plus cross-cluster collision resolution.
  • An LLM runs only as an optional validator. Generation itself uses no LLM.

Redesign (LLM-driven)

  • An LLM generates coherent, context-aware fake personas per cluster, mapped onto the IR clusters.
  • A replacement map records every original → fake decision, so each occurrence is faked consistently across the run, even though the same surface string can now belong to different entities.
  • The deterministic router stays for format-preserving types (phone, IDs, cards, IP/MAC, coordinates, DOB).
  • This is where the pipeline's LLM budget now lives, freed up by dropping it from detection.

4 · Replacer

Substitute the anonymized clusters back into the document.

The replacer takes the anonymized clusters (a flat map of original value to fake) and writes them into the source text. It matches each occurrence by exact value plus case variants, substitutes any UUID placeholders, and falls back to a format-preserving replace for anything unmatched. Mechanically it barely changes; it just consumes the new, semantically coherent fakes.

Next steps

The complete redesign is two weeks out at the earliest. In the meantime we ship the part that's already done, and start building the data to train the rest.

  1. Dual-engine prod (now). Sahil's updated 259-feature IR engine is ready, so we're wiring the live prod pipeline to run through either IR engine — the current one or the new one — and validate the new engine in production while the full redesign proceeds.
  2. Generate synthetic data. Mint a large synthetic corpus to train against the new taxonomy.
  3. Train the detector. Train the bi-encoder on that data.
  4. Train the new IR. Train the merger on the new 3-cluster taxonomy.
