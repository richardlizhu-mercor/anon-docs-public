Taxonomy evolution. The label set narrowed and re-shaped across five generations: (1) deberta_ft_v2 (07-07) — legacy ~14-type fine-grained. (2) pb2-fixdrop (07-29) — broad 16-type fine-grained (adds First Name, Nickname, GPS; symmetric B/I); the Qwen runs reuse this-era 16-type set. (3) v4 A/B/C (08-04) — three parallel label-scheme experiments off pii-bench-v4: A = 11 target types, non-target→O; B = 11 + a single Other head; C = full 18 + ID-collapse (only C keeps Phone/URL/…). (4) v5 D/E (08-05) — NES (Name/Email/Street, 5 name subtypes→one Name); D routes other PII→negative, E routes other PII→one Other. E (Other-head) won (v3.3 0.915 vs 0.718; Email 0.855 vs 0.091). (5) v5.1 / v5.2 (08-08) — collapsed 5-type Name / Org / Address / Email / Other (Other-head), championDebertaCategories = 5. Pipeline-wide migration: head-scores width 17→6; champion Other masks as a generic Identifier (format-preserving) but is never clustered / join-keyed.
Champion / challenger promotion history. Two distinct events:

PR #188 (ANON-212, DRAFT — never merged, 2026-07-30): proposed champion → deberta-v3-base-pb2-fixdrop (config-only; the default detector flips gliner→deberta), challenger → qwen2.5-7b-qlora (191643Z). Blocked on maintainer sign-off (a 3rd product-path Python scanner, unverified GPU at the time, undefined deploy target).

PR #295 (ANON-324 — MERGED 2026-08-10T03:48Z, squash f90cf2ee, by wth-lg): final state = champion deberta-pii-v5.1-3ep, challenger deberta-pii-v4.1-e. The challenger changed twice in review: v5.1-2ep (2nd in the ranking) → deberta_ft_v2 (old 14-type; champion/challenger taxonomies made independent) → v4.1-e (final; detector labels re-synced to the 7-type union). v3.4 ranking (32,367-doc sample) char F1: v5.1-3ep 0.755 > v5.1-2ep 0.747 > v5.2; Gemini reference 0.733.

Why v5.1 over v5.2 — in-distribution vs real target. v5.2 is the best in-distribution model (Detect F1 0.844 on its own pii-bench-v5.2 test), but v5.1-3ep generalizes better to the real anonymization target — contigo-parity 0.954 — so it was promoted. The lesson from the whole line: rank on the real corpus (contigo), not in-distribution benchmark F1, which flips the winner.
Training & inference recipe. DeBERTa-v3-base, full-bf16 weights on an A100 (fp32 → NaN on this stack; bf16-autocast → all-O collapse), cast to fp32 before save_model; 256-token windows / stride-64 overflow; overlap span→BIO; load_best_model_at_end on fine_f1. Typical cost: train ~2 epochs / 464–500k docs ≈ 3–3.1 GPU-hr ≈ $11–12 (A100 @ $3.67/hr); infer 266k docs ≈ 0.11 GPU-hr ≈ $0.08, ~680 docs/s batched on one L4 ($0.71/hr). Checkpoints promote to s3://data-acq-raw-prod/_models/detection/.

Conventions

Metric. Headline numbers are char-level F1 (PII-or-not over characters). Span metrics: IoU≥50% / ≥75% / exact (IoU=1.0). Reported P/R separately where GT bias matters.

Benchmarks & their GT bias (see the Benchmark Versions & Changelog): pii-bench-v4/v4.1 = clean typed GT (trust for ranking); contigo v3.1 = diff GT (recall-biased); v3.2 = mapping GT (precision-biased); v3.3 / v3.4 = authoritative exact-mapping + LLM-typed (the ranking GT). Numbers are not comparable across GT variants — a model's v3.1 and v3.3 F1 measure different things.

"In-scope" F1 masks out-of-scope GT so a narrow detector (e.g. NES) isn't penalized for types it never targets.
