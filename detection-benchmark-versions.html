Provenance — the v4 → v5.2 line splits into two roles. Everything from v4→v5 is one shrinking, audit-cleaned EVAL benchmark (train/val/test, full 37-type gt_type taxonomy). v4 was re-derived from the original HuggingFace sources; v4.1 is an audit-driven cleaning pass (DACQ-3665) that removed 7,178 train + 559 val docs which were exact duplicates of eval docs (so 0 cross-split exact dups remain; test untouched at 62,359) plus offset/type/overlap fixes, dropping train 499,624→492,446 and val 62,414→61,855 — its manifest is deliberately authoritative=false and enumerates known limitations (notably ~487 test + 440 val near-duplicate template-leakage docs that are soft leakage and were NOT removed). v5 is that same v4.1 corpus with the audit fixes applied inline and annotated per span (relabeled_from 1,977, boundary_fixed_from 877, added_by 987, corrected_surface 30, suspicious 4,934); same split sizes, 948,962 train spans.

v5.1 and v5.2 are a different animal — TRAIN corpora, not eval benchmarks. Both are train-only with no val/test and a 5-class collapsed label set (Name / Org / Address / Email / Other, label key type), so they must never be scored as a benchmark. Each blends cleaned v5 with a downsampled fully-synthetic Vibecorp run (run-4061225: gmail/slack/linear); v5.2 additionally adds 10,000 Gemini hard-negatives (name-shaped non-names carrying empty spans, to suppress false positives on Name). The only knob that differs is the Name-span mix: v5.1 = 70% v5 / 30% synthetic (832,751 docs / 1,380,341 spans), v5.2 = 80% v5 / 20% synthetic (700,462 docs / 1,199,883 spans). Critically, the synthetic content is fully fake — it is NOT anonymized customer data and contains no real PII. The v5 audit annotations do not survive the collapse; v5.1/v5.2 spans carry only {start, end, type}.

Provenance — contigo-bench v3.3 & v3.4 (exact-mapping family). A newer, authoritative GT line: instead of inferring boundaries by diff (v3.1) or locating mapping values (v3.2), v3.3/v3.4 take the anonymizer's own detected character offsets directly from a Sisyphus run's _changes/<service>.jsonl ({doc_id, spans:[{start,end,surface,fake}]}) — boundaries exact by construction. row_id is the 1-based processed-CSV row index (raw_cell = data[row_id-1][column]), validated to reconstruct every cell with 0 offset mismatches. Each span's attribute type is assigned by Gemini 2.5 Flash (Vertex) over an 18-label taxonomy given service+column context. Same service:table:row_id:column doc_id and positive/negative model as v3.1/v3.2.

v3.3 = zohobooks from Sisyphus sisyphus_20260730T032600Z (PR #223 / ANON-265). v3.4 = confluence + jira + msteams + zohobooks from the sisyphus_20260806T023947Z batch. Deferred — gmail & googledrive: persona-scoped runs (a single persona, re-ordered view) whose _changes row-ids can't be reconstructed from the raw CSVs without a stable per-row key (message_id / drive file-id) from the Sisyphus side. Everything else (confluence, jira, msteams, zohobooks) reconstructs exactly.

Conventions (both benchmarks)

Offsets are codepoint (CP), not byte. Spans are text[start:end] Python slices — verified on non-ASCII (a byte read is shifted). ~6.5% of spans diverge cp≠byte on accented/CJK text. Use cp in Python eval; the Rust masking engine uses byte.

doc_id (pointer). Contigo: service:id / service:table:row_id (mixed, legacy). pii-bench: source:parquet-row-index (e.g. few_nerd:0) — joins to GT + all model preds. Fine-grained synthetic-world detection data uses the standardized 4-part pointer service:table:row_id:column (a row has multiple PII columns; offsets are per column value).

Brand / Product not tagged. Both benchmarks fold brand/product/org into Organization Name (Institution cluster). An LLM pass showed the distinct Brand/Product split is ~1% of spans — not worth a separate type; the more useful finding was the mislabels fixed in v2/v3.
