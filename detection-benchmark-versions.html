v3.1 method (diff): per-column word-diff + difference-trim → spans = the exact pre/post change. 6,844,424 spans.
v3.2 method (mapping): locate exact original values (Aho-Corasick, word-boundary + whitelist) from the sheet "[INT] Contigo — Canonical Anonymization Mapping [v4]" (1-bEXSmvNnShpMHU8STlDOxShDuOORJNVnefOYjeT8jM, owner nathanaeltjandra@mercor.com) — 182,607 originals from tabs: [c] Account Name (brands), 1:1 Deterministic Name Map, Instagram Handle, [c] Industry, [c] Internal Team (Gmail/Teams), Gmail 7.20, MySQL Extras, JIRA; whitelists COMMON WORDS + Whitelist 2 (2,238 terms) — applied to the same text units. 5,105,685 spans.

v3.1 vs v3.2 = diff-inferred boundaries (higher recall, full coverage) vs mapping-exact boundaries (higher precision, sheet-limited coverage). Validation on a 7,500-doc slice: v3.1 9,297 spans vs v3.2 5,307 — e.g. Swetha Ramesh is one v3.1 span but two v3.2 tokens [Swetha][Ramesh]; Harsh Patil→[Patil] (v3.2 misses Harsh, absent from the sheet).

Conventions (both benchmarks)

Offsets are codepoint (CP), not byte. Spans are text[start:end] Python slices — verified on non-ASCII (a byte read is shifted). ~6.5% of spans diverge cp≠byte on accented/CJK text. Use cp in Python eval; the Rust masking engine uses byte.

doc_id (pointer). Contigo: service:id / service:table:row_id (mixed, legacy). pii-bench: source:parquet-row-index (e.g. few_nerd:0) — joins to GT + all model preds. Fine-grained synthetic-world detection data uses the standardized 4-part pointer service:table:row_id:column (a row has multiple PII columns; offsets are per column value).

Brand / Product not tagged. Both benchmarks fold brand/product/org into Organization Name (Institution cluster). An LLM pass showed the distinct Brand/Product split is ~1% of spans — not worth a separate type; the more useful finding was the mislabels fixed in v2/v3.
