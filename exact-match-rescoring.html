Exact-Match Re-scoring — Contigo & pii-bench

The same predictions as the leaderboards, re-scored at the span level: a detection counts only if the entire span matches exactly (identical [start,end)), not merely overlaps. This isolates boundary quality, which char-overlap scoring hides.

Why boundaries drift. The DeBERTa detectors decode BIO labels per subword token and emit each tagged token's char offsets. With SentencePiece this produces (1) subword truncation — Vanshita → shita when the model tags only the trailing subword — and (2) leading-space inclusion — Annan →  Annan. There is no snap-to-word-boundary step. qwen generates the literal surface string, so its boundaries are exact.

Read the columns as a strictness ladder: char F1 (the leaderboard metric, char-overlap) → span ovlp (span TP if it overlaps any GT span) → trim exact (boundaries equal after trimming whitespace) → EXACT (boundaries identical). That trim exact ≈ EXACT for the encoders proves the drift is mid-word subword truncation, not whitespace — trimming doesn't rescue it.

Takeaway. Char-overlap scoring rewards "roughly right region"; exact-match rewards "right span." If downstream consumes exact spans (masking the precise PII, not a drifted window), the generative qwen is far ahead and the encoders need a boundary-repair / word-snap post-process before their leaderboard F1 reflects usable output.
