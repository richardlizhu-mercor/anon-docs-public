At a glance

Production detectorscan_deberta — a DeBERTa-v3 token-classifier, reimplemented in Rust on Candle (one binary; CPU / Apple Metal / NVIDIA CUDA at compile time).
Champion masksdeberta-pii-v5.1-3ep — 5 coarse types (Name / Org / Address / Email / Other, 11 BIO labels). Best on contigo-bench v3.4. Its output feeds masking + identity resolution.
Challenger shadowdeberta-pii-v4.1-e — runs in shadow every default run, stored under detect/challenger/ for comparison only, never masked. Champion & challenger need not share a taxonomy.
Alternate lanescan_modernbert — HiveTrace GLiNER-Guard mmBERT uniencoder (~147M, 8192-ctx), 4 canonical types (person / email / phone / SSN). Set detector: "gliner" (the config default) vs "deberta".
Detection contract{email, type, value, score, start, end, model} JSONL — byte offsets into the source cell; model ∈ {gliner, deberta}. The detector-agnostic handoff to masking + IR.
RuntimeGKE detect stage (A100 / L4), one Indexed-Job pod per shard. Pure-Candle inference; ORT only in the offline validation lane.
Throughput~35,435 tok/s per A100 (fp16, drop-free); ~860K tok/s across 16. A 68.5 GB run ≈ 36 min, ≈ $17.

How it works

The corpus is de-duplicated, only unique chunks are scanned across N GPUs, results are cached in a content-addressed PII table, and detections are re-joined to every occurrence — so repeat runs approach zero GPU cost. Dedup is the cost lever: word-snapped FastCDC@128 removes ~50% of GPU tokens (71–79% chunk-level duplication on real 20–89 GB corpora).

corpus.parquet └─ prepare ─▶ dedup (word-snapped FastCDC) ─▶ unique chunks + occ back-refs └─ piistore filter ─▶ drop chunks already scanned (content-addressed cache) └─ detect ─▶ scan_deberta (champion) + scan_deberta (challenger, shadow) on N × A100 └─ canonical detection JSONL {email,type,value,score,start,end,model} └─ resolve ─▶ map eid → global gid, validate types vs the model's taxonomy └─ mask ─▶ {{uuid}} tokens + per-column mapping.json └─ identity resolution ─▶ clusters.json (detect → IR handoff)

New full-corpus runs use the GKE controller (orchestration/) that chains detect → mask → IR behind one digest-pinned image; the legacy manually-driven GCE fleet (fleet.sh) is retained for benchmarking. Every asset — scanner binary, model weights, tokenizer, config — is pinned by an exact GCS generation, so a run is fully reproducible.

Detector lanes

Five execution lanes exist; two are production-relevant. The DeBERTa token-classifier (scan_deberta, Candle, 256-ctx, BIO decode) is the shipped champion/challenger path. The GLiNER-Guard uniencoder (scan_modernbert, Candle fp16 + optional flash-attn, 8192-ctx) is the all-GPU fleet lane with clean whole-entity spans. The Candle DeBERTa encoder is validated bit-faithful against an ONNX-Runtime oracle (cosine 1.00000000, max |diff| 1.1e-4); production inference imports no ONNX runtime at all.

Alpha quality. This is a research pipeline extracted from a working lab repo — the measured numbers are real, but file formats, flags, and the fleet driver may change, and error handling is fail-fast. Test small (N=2) before scaling.

Training data & recipe

The champion is microsoft/deberta-v3-base fine-tuned into a PII token-classifier (train_deberta_v3.py). deberta-v3 is the v2-architecture backbone Candle's DebertaV2 can execute, so the checkpoint loads straight into the Rust scanner.

Corpus~5k docs / ~9k spans, ~40% span-free negatives — {doc_id, text, spans:[{start,end,type}]}.
SourcesSynthetic (bulk) — synthetic-world slack/gmail/linear docs with the generator's coordinate-exact ground truth. Real-company — real extracted docs labeled by Gemini distillation, remapped to the taxonomy. (Use ground truth where you have it; distill only where you don't.)
TaxonomyTrainer targets 16 fine types / 33 BIO labels; the shipped v5.1 champion emits 5 coarse types (Name / Org / Address / Email / Other). Label set is read from the checkpoint's config.json.
Recipe gotchaFull bf16 weights only. fp32 NaNs on Apple; bf16 autocast collapses DeBERTa-v3 to all-O (train loss drops, eval F1 stays 0). GPUs train full bf16; checkpoint cast back to fp32 before saving.
Cost5 epochs, ~23 min on a T4 (or Modal). Held-out fine-F1 ≈ 0.87, detection-F1 ≈ 0.89–0.92.
ExtendingContinued fine-tune (expand label head + replay) teaches a new type without forgetting the existing ones — no customer strings committed. A generative Qwen2.5-7B QLoRA extractor is an alternate detector shape.

Results

Detector bake-off on identical input, all through the real GKE detect stage (DETECTOR_COMPARISON):

DetectorTypesCharacter
GLiNER-Guard (prod)4Fewest, highest-confidence (0.93–1.00), clean whole-entity spans; narrow taxonomy.
Gemini (data-acq)14Broadest coverage — only detector catching org / brand / product / username / city-state-zip / DOB. Slowest, most expensive.
DeBERTa-v35Detects the right regions (recall on canonical PII is sound); weakness is span boundaries — the window / BIO-decode + merge step fragments entities, not the weights.

Detectors converge on the real entities (17 spans flagged by all four detectors, 33 by three of four); disagreement concentrates in span boundaries and the long tail of single-detector types. The champion was selected on contigo-bench v3.4. Living, drill-down results — full-corpus F1 by model, by PII type, and exact-span vs character-span — are in the hosted leaderboards below. Recurring finding across benchmarks: overall F1 falls with model size on out-of-distribution data (encoder base 0.70 → 7.6B qwen 0.31), and exact-span scoring collapses the encoders (~0) while the generative qwen leads (~0.79).

Performance & cost (measured)

GPU throughput~35,435 tok/s per A100 (fp16, all-GPU, drop-free); ~860K tok/s across 16.
Reference run16 flex-start A100, 68.5 GB: 12.98M unique chunks, 28.7% cache hit, ~36 min wall, 6.09M PII spans, ≈ $17.
Full E2E masking2.67M rows: ~27 min on 64 A100 / ~24 min on 128 (GPU scan dominates; CPU dedup/mask stages parallelize ~3.6–5.8×).
Cache leverDedup removes ~50% of GPU tokens; the content-addressed table skips ~29% more on fresh similar data, ~100% on re-runs.
