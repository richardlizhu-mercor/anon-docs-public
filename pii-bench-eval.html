PII Tokenizer — pii-bench Re-run (16-type)

Every detector from the options bake-off, re-run on the external pii-bench test split (Pritesh-2711/pii-bench) instead of anobench, scored to the 16-type taxonomy — with measured runtimes this time, not compute-ratio estimates. Two stratified samples: 1500 (5 PII sources) and 5000 (all 10 sources).

Accuracy = char-level F1 under the 16-type taxonomy (harness score_new_taxonomy.py): detection (PII-or-not), cluster (Identity/Street/Institution/N-A), fine (exact type). Timing = measured on one Apple-Silicon Mac (MPS for torch models, CPU for spaCy/Presidio, google-genai API for Gemini), per-process via /usr/bin/time -l. pii-bench GT is coarser + noisier than anobench, so absolute F1 is not comparable to the anobench doc — read the columns against each other, not against the old numbers.

The fine-tune's home-field edge doesn't transfer; Gemini's lead widens On anobench (Mercor's own distribution) deberta_ft was the "best value" frontier point at 0.874 — it beat zero-shot gliner2. On pii-bench, an external corpus neither the fine-tune nor the Gemini prompt ever saw, that edge evaporates: the fine-tuned deberta_ft (0.620 clean-source detection, 5k) lands mid-pack — roughly on par with the zero-shot gliner family (gliner2 0.619) and below the routed union (0.685). It doesn't collapse, but its in-distribution lead is gone — on anobench it beat gliner2; here it merely ties it. Meanwhile Gemini leads at 0.769 — ~0.084 over the best local, an order of magnitude wider than anobench's 0.009 gap. The read: fine-tuning buys in-distribution accuracy, but on an unseen distribution zero-shot detectors generalize at least as well, and the cloud LLM's margin grows. (deberta_ft here uses the training-matched sliding-window inference; qwen is scored on the full sample.)

Read the per-source spread pii-bench GT quality varies a lot by source, so the clean-source aggregate above is the honest headline. The cleanest, richest PII is nvidia_nemotron and gretel_finance — that's where scores reflect real detector skill. The rest carry artifacts: ai4privacy_400k's GT is sparse and dominated by out-of-scope labels (FINANCIAL_ENTITY / IP / LOC), so detectors that correctly find emails/usernames there get charged as false positives — every model (even Gemini: recall 0.92, precision 0.14) scores low, which is why the "all-sources" column is depressed. isotonic_pii_200k mislabels common words ("Male", "9 years old", greetings) as names and user-agent strings as usernames, and a handful of its GT spans sit in dense concatenated strings our BIO→char aligner can't place — both slightly understate precision there. finer_139 (5k only) is XBRL financial tagging with zero in-scope GT, so every model reads 0.000 in that column — a pure false-positive probe, not a detection score. Treat all these columns as a precision stress-test, not a skill ranking; the clean-source aggregate is the number to rank on.

Method

  • Dataset: pii-bench test split (5,000-doc / 1,500-doc stratified samples, seed 42, text 15–4000 chars). pii-bench GT is token-BIO; converted to char spans (token-align 99.5% / 99.7%, 100% surface-consistent) and crosswalked from 82 pii-bench labels into the 16-type taxonomy (in-scope GT spans: 3,614 / 8,050).
  • Out of scope (dropped from GT, never TP/FN): IP/MAC/PAN, City/State/Country/Postal, generic Date/Time, financial-entity/XBRL, sensitive attributes (gender/religion/health), etc. — only the 16 types count.
  • Reading the fine column: pii-bench GT does carry First / Last / Full Name as distinct labels, so name subtype is fine-scored. Detectors that emit only a coarse person label — notably Gemini (fine-F1 = 0.000 on names despite high support) — score ~0 there, so fine understates a coarse detector's real skill. Read detection (the headline) for "did it find the PII" and fine as a subtype-resolution metric that structurally favors detectors emitting First/Last/Full directly.
  • spaCy fine-F1 ≈ 0 by construction: it emits only coarse OntoNotes NER (PERSON/ORG/PRODUCT), which never resolves to a fine PII subtype — it's an NER model, not a PII-complete detector (as in the bake-off).
  • Distribution shift: deberta_ft and Gemini were tuned/prompted on Mercor data, not pii-bench — these numbers measure transfer to an external distribution, not in-domain skill. deberta_ft runs the training-matched sliding-window inference (256-token / 64-stride overflow) so no GT is lost to truncation.
  • Scoring detail: overlapping typed predictions are resolved highest-confidence-wins at the char level (so a nested Email+URL or Name+subtype span doesn't penalize the higher-confidence type). qwen is scored on the full sample. gliner2_ft (a doc frontier point) isn't here — its LoRA config was purged; routed uses OOB gliner2 (as its label says). StarPII is HF-gated (skipped if unauthenticated).
