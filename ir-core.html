IR v2 — core architecture

The current EAG-free identity-resolution engine, distilled to its spine: what each stage does, and the two learned knobs that decide every merge.

Core architecture feat/ir-eag-free-engine apps/server/data-acq Updated July 2026
The one-line mental model Ingest once, route by type, then fan out per type through a learned chain — encode → block → score → reduce → cluster — re-key global→local exactly once, and fill in the singletons. Only S3 keys cross the Temporal boundary, and only two learned knobs, τ (the merge threshold) and γ (the Leiden resolution), decide merges. Both are learned, not tuned.

The job, and what changed

The job hasn't changed: collapse the many surface forms of a person, org, or place into one identity, so the faker can substitute a single fake for every occurrence. What changed is the machine. The old engine was one 2,526-line activity that embedded values with MiniLM, scored candidate pairs with a hand-tuned cosine combiner, and ran a global Leiden pass with hand-tuned resolution tables. The rebuild replaces all of that with a learned, order-invariant pairwise merge decision: a trained model scores each candidate pair, and clustering composes those decisions. The payoff is precision under scale, which is exactly where the old engine degraded.

The core idea: decide per pair, then cluster

Instead of folding signals into edge weights and cutting one global graph, the engine asks a trained model a direct, symmetric question for every candidate pair: are these the same entity? Because every feature is symmetric in the two values, the answer doesn't depend on order. That calibrated P(merge) is the whole decision. Everything downstream just composes those per-pair answers into clusters, carefully.

The stages, briefly

encode · Modal GPU

Qwen LoRA encoder

A shared Qwen3-Embedding-0.6B base with 5 frozen per-type LoRA adapters (Identity, Org, Brand, Product, Street) turns each value into a 1024-d vector on a warm Modal GPU. It's a matcher, not a generic sentence embedder: recall@50 measured 0.95 vs bge's 0.80. No CPU fallback — if the encoder is down, the run stops rather than silently embedding with the wrong model.

block · S3

Candidate generation: three arms, three columns

Blocking cuts O(n²) down to candidates using FAISS kNN (k=200, streamed), the co-occurrence graph (values sharing a (service, table, row)), and token/cross-attribute blocks. The three signals stay in three separate columns because the model reads them apart.

featurize + score · S4

259-feature bank + GBDT

One vectorized calculator produces a 259-column vector per pair, and the same function runs at train and serve time, so there's no skew. A LightGBM raw Booster plus a small 1-D calibrator turns that into a calibrated P(merge). The old 19 production features are still here, re-homed into their families.

the operating point · learned

τ and γ — the only two knobs that decide merges

Both are learned per type on the calibrated probability scale, via a train-through-serving harness that runs fixtures through the exact serving code. τ, the merge threshold, uses a starvation-aware rule: hold a 0.95-precision floor unless that floor can only be met at recall below 0.10, then fall back to F1-max. γ, the Leiden resolution, sits between the negatives' P90 and the positives' P10, capped just under the positive floor so it can't collapse. There's no default table anymore: resolution goes operator-override → bundle → fail-loud for τ, or singleton for γ.

cluster · S5 → S8

Reduce → components → per-component Leiden → constraints

Keep the edges above τ, break them into weakly-connected components (a P≥τ edge never crosses a component, so this loses nothing), then run Leiden per component at the learned γ. Hard constraints finish the job: CANNOT-LINK applies as a pure final split (five predicates, including different-last-name and different-role-same-row), and MUST-LINK covers exact-normalized equality. Co-occurrence is never a MUST-LINK; it's soft evidence only. The ~97% of nodes with no surviving edge are refilled as singletons at the end, so every value reaches the faker.

substrate · co-occurrence

The co-occurrence signal

Co-occurrence is the evidence the encoder can't see: two people named "J. Smith" never share a row, but a person's name and email sit in the same one. It's rebuilt from the nodes' service-qualified (service, table, row) self-join, with a role gate that drops cross-person links (a sender and a recipient in one email row don't merge). It shows up as a candidate arm, a Leiden weight, and ~43 of the 259 features.

orchestration · Temporal

Per-type fan-out

The run is a Temporal IRFanoutWorkflow: route once, fan out one durable unit per cluster type across a sliding window of 4 on a dedicated 64-concurrency worker, then build once. A failure retries one stage of one type instead of the whole world, and only S3 keys and scalars cross activity boundaries, so history stays flat regardless of data volume.

Two things both called "EAG" The Enterprise Activity Graph is the north-star typed activity graph; IR is "Stage 1" of it, and it feeds IR drop-in pair features (that's the sense of "features from the EAG"). The Embedding-Anchor-Graph is the old live-LLM-judge path this branch deletes — which is what "eag-free" refers to. Same acronym, different thing. Today's engine gets the activity-graph signal from the structured (service,table,row) self-join; the fuller typed graph and cross-modal documents are future work (DACQ-2809).

The decisive result

Both engines were scored by the same metric code on the same two synthetic fixtures. The trend is the story, not any single point: HEAD improves as the dataset grows while main degrades, and HEAD is far more precise at representative scale (fewer of the privacy-risky wrong merges).
