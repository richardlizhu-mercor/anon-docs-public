OpenAI Privacy Filter — Benchmark

Reproducing OpenAI's Privacy Filter on ai4privacy/pii-masking-300k with its own opf eval harness, and measuring how it transfers to the unseen Pritesh-2711/pii-bench distribution.

Verdict — replicated. On the full 47,728-row ai4privacy validation split (OpenAI's exact eval set), the released openai/privacy-filter scores token F1 0.954 and span F1 0.9199 — landing on the model card's baseline (0.960 / 0.926), ~0.6 pt under. The residual is the card's documented dataset FP/FN cleanup (baseline→corrected 0.960→0.974 token, 0.926→0.942 span), which we did not apply. On the unseen pii-bench distribution the same model drops to span F1 0.388.

The model

  • Bidirectional token classifier, gpt-oss-like: 8 pre-norm blocks, d_model 640, GQA + RoPE, sparse MoE (128 experts, top-4). 1.5B params / 50M active. 128k context.
  • 8 categories → 33 BIOES token classes; constrained Viterbi decode into coherent spans.
  • Run here as the released checkpoint via opf eval, dense-MoE path on Apple MPS.

Method

ai4privacy — the validation split (47,728 rows, 6 languages; per-language counts match the card's Table 6 exactly). Each row's privacy_mask char-spans are mapped to PF's 8 categories via the model card's §7.2.1 crosswalk, excluding categories with no PF definition (TIME/SEX/STATE/COUNTRY/CARDISSUER). Scored --eval-mode typed. pii-bench — the repo leaderboard fixtures, scored --eval-mode untyped (span detection ignoring the differing taxonomy, plus per-type recall).

Metrics (model card §7.3): token detection = PII-or-not per token; span detection = char-level containment match, whitespace-trimmed. recall=TP/(TP+FN), precision=TP/(TP+FP), F1=2PR/(P+R). Our numbers are as-provided — only the category crosswalk, no dataset cleanup — so they sit at/just below the card's baseline by construction.

Why the gap

  • Taxonomy mismatch. pii-bench counts Organization (recall 0.04) and URL/Domain (0.18) as PII; PF doesn't model them. These alone cap achievable recall.
  • Distribution shift. ai4privacy is PF's training-style distribution (synthetic letters/forms); pii-bench aggregates 10 heterogeneous sources (finance NER, nemotron, isotonic, …).
  • Boundaries. Containment matching penalizes fragmented/partial spans that token-level scoring forgives (span F1 < token F1 on both datasets).
